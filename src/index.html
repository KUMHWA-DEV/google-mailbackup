⚠️ 주의사항
  • 로그인은 반드시 회사 계정으로 하세요. 개인 Gmail로 로그인하면 백업 폴더가 없어 "시트를 찾지 못했습니다"가 뜹니다.
  • 기본(읽기 전용)은 Drive와 스프레드시트 읽기 권한만 요청합니다. Gmail이나 메일 발송 권한은 요청하지 않습니다. 실행 모드를 켜면 Gmail 읽기·Apps Script 실행·알림 발송 권한이 추가되고 그 토큰이 내 PC(~/.config/mail-backup-mcp)에 남으니 필요한 사람만 켜세요.
  • 설치 명령은 본인이 터미널에서 실행하세요. AI 앱에 "이 명령 실행해 줘"라고 시키면 대부분의 AI가 외부 코드 실행을 거부합니다.
  • AI는 내 계정으로 백업된 파일만 읽습니다. 다른 직원의 메일은 볼 수 없습니다.
  • 첫 실행은 패키지를 내려받느라 1~2분 걸립니다. 회사 네트워크가 GitHub이나 npm 접속을 막으면 설치가 실패합니다(IT에 문의).
❓ 자주 묻는 질문 · 오류가 났을 때
"node: command not found" / "'node'은(는) 내부 또는 외부 명령이 아닙니다"
Node.js가 없거나 터미널이 설치 전에 열려 있던 겁니다. 1단계대로 설치한 뒤 터미널(PowerShell)을 닫았다가 새로 열어 다시 실행하세요.
"git: command not found" / "spawn git ENOENT"
설치 명령은 GitHub에서 코드를 받으므로 Git이 필요합니다. Mac은 안내 창이 뜨면 "설치"를 누르거나 터미널에 xcode-select --install, Windows는 PowerShell에 winget install Git.Git 후 터미널을 새로 여세요.
명령을 실행했는데 AI 앱에서 도구가 안 보여요
앱을 완전히 종료했다가 다시 열어야 합니다(창만 닫는 것은 종료가 아닙니다). Claude Desktop은 메뉴 막대/작업 표시줄 아이콘에서 종료하세요.
첫 질문을 했는데 로그인 창이 안 열려요
같은 질문을 한 번 더 해 보세요. 그래도 안 뜨면 AI의 답에 포함된 로그인 주소를 브라우저에 직접 붙여넣으면 됩니다.
"액세스 차단됨 · redirect_uri_mismatch"
관리자 쪽 OAuth 클라이언트 설정 문제입니다. 관리자에게 알려주세요(데스크톱 앱 유형이어야 합니다).
"Drive에서 'Mail Backup Index' 시트를 찾지 못했습니다"
이 계정으로 백업이 한 번도 안 됐거나, 개인 계정으로 로그인한 경우입니다. 이 웹앱에서 백업을 먼저 실행하고, 로그인은 회사 계정으로 하세요.
실행 모드에서 "권한이 없습니다" / 403
읽기 전용으로 먼저 로그인한 뒤 실행 모드로 바꾼 경우입니다. ~/.config/mail-backup-mcp/token.json을 지우고 다시 질문해 새 권한으로 로그인하세요. 계속 실패하면 관리자에게(스크립트의 GCP 프로젝트 연결).
AI가 "출처를 신뢰할 수 없다"며 진행을 거부해요
AI에게 설치를 시킬 때 나오는 반응입니다. 명령은 본인이 직접 실행하고, AI에게는 질문만 하세요.
처음부터 다시 하고 싶어요
Mac 터미널: rm -rf ~/.config/mail-backup-mcp · Windows PowerShell: Remove-Item -Recurse -Force ~/.config/mail-backup-mcp 를 실행하고, 설치 명령을 다시 실행하면 앱 설정 항목이 새로 덮어써집니다.

🔑 관리자 · MCP용 OAuth 클라이언트

소유자에게만 보임

GCP 콘솔 → API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 유형 데스크톱 앱 → JSON 다운로드 → 내용을 아래에 붙여넣고 저장. 같은 프로젝트에서 Drive API·Sheets API를 켜 두세요. 등록하면 직원들의 프롬프트와 다운로드 버튼에 자동으로 들어갑니다.

📥 예전 백업 가져오기 (.eml · .mbox)

백업과 별도로 동작
1
파일을 이 폴더에 넣기
내 드라이브 › Mail Backup › _import —
.eml, .mbox, 압축된 .mbox.gz, Google Takeout이 준 .zip을 그대로 넣으면 됩니다(압축을 풀 필요 없음). mbox 여러 개와 eml 수천 개가 섞여 있어도 되고, 하위 폴더에 나눠 넣어도 됩니다(폴더 이름은 분류에 쓰지 않습니다).
2
가져오기 시작
오른쪽 ▶ 가져오기 시작을 누르면 서버가 메일을 한 통씩 해석해 메일 자체의 속성으로 분류합니다. Gmail 내보내기(mbox)의 라벨 정보가 있으면 백업과 똑같은 규칙(사용자 라벨 › 보낸편지함 › 받은편지함 › 보관됨)으로, 없으면 보낸사람이 나면 보낸편지함·아니면 받은편지함으로 넣어 같은 폴더에 저장합니다. 컴퓨터를 꺼도 계속되고, 백업과 동시에 돌아도 됩니다.
3
끝나면
메일함에서 다른 메일과 똑같이 검색·열람됩니다. 처리한 파일은 기록되어 다시 처리되지 않으니 _import 폴더는 비워도 되고, 파일을 더 넣고 다시 시작하면 새 것만 처리합니다.

라벨은 이 계정의 Gmail에 실제로 있는 라벨만 폴더로 만듭니다. 내보내기 파일에 섞여 있는 Gmail 내부 표시("열림", "수신확인 보냄", "…카테고리" 등)는 무시하고, 이미 지운 라벨의 메일은 받은편지함·보관됨으로 갑니다. 옛 라벨을 살리고 싶으면 Gmail에서 같은 이름의 라벨을 먼저 만든 뒤 가져오세요.

지원: .eml(30MB까지) · .mbox · .mbox.gz · .zip(4GB까지, 안의 .mbox/.eml) — GB급도 4MB씩 스트리밍으로 읽고 풀면서 처리하고, 구간이 끝나면 압축 해제 상태를 저장해 다음 구간에서 그 자리부터 이어갑니다 · multipart · base64/quoted-printable · UTF-8/EUC-KR 등. 같은 메일(Message-ID)이 여러 파일에 있어도 한 번만 저장됩니다. Outlook .pst/.msg는 먼저 .eml이나 .mbox로 변환해야 합니다.
